**Указатель** (pointer) - это переменная, которая хранит адрес ячейки памяти.
# Разименование переменной
 ```C
 char a = "A"; // 65
 char *ptr;
 prt = &a;
 *ptr = 67;
 ```
 Это называется **разыменованием (dereference)**: мы переходим по адресу из указателя и **читаем оттуда или пишем туда значение**. Поэтому и важно знать, на что указывает указатель: здесь это `char`, а `char` занимает ровно 1 байт - значит, при разыменовании заберём ровно один байт
 >[!warning]
 >**Важно:** не путаем `*` при объявлении и при разыменовании - это разные вещи:
 >- `int *ptr;` - `*` здесь значит, что мы объявляем указатель
 >- `*ptr = 5;` - `*` здесь означает операцию разыменовывани
# Указатель на void

Указатель на `void` хранит адрес, как и любой другой указатель. А что будет, если его разыменовать?

```c
int a = 5;
void *ptr = &a;
*ptr = 3; // ошибка!
```

Получим ошибку: у `void` нет размера, и, перейдя по адресу из `ptr`, мы не знаем, сколько байт читать или писать.
Тем не менее `void *` встречается постоянно: его используют как универсальный указатель - передают просто адрес, а потом явным преобразованием превращают в нужный тип. Так работают `malloc`, `memcpy` и `qsort`.
```C
int a = 5;
void *ptr = &a;

char b = *((char *)ptr); // преобразовали к char * и разыменовали, вытащив 1 байт в переменную b
```

`#define NULL ((void *)0)`
У указателей есть свой ноль - `NULL`. Если в VS Code навести на него мышкой, увидим, что это 0, **явно приведённый** к указателю на **void**.

# Динамические массивы
Динамические массивы - массивы, размер которых можно менять по ходу выполнения программы. Заголовочный файл - `<stdlib.h>`. Функции для работы с динамическими массивами:

- `malloc()`
- `calloc()`
- `realloc()`
- `free()`
## malloc()
`malloc` (memory alloc) **выделяет динамическую память**. Мы просим у кучи (heap) кусок памяти для дальнейшего использования. У `malloc` один **аргумент - количество байт, которое нужно выделить**. **В случае успеха возвращает адрес выделенной памяти, а в случае неудачи** (например, память кончилась) - **NULL**, с которым мы уже знакомы.

```c
// Выделяем 12 байт (3 размера int)
int *arr = malloc(3 * sizeof(int));
```
- В случае успеха:
    - В переменную arr запишется адрес, который указывает на выделенную память. В выделенной памяти у нас будет доступно 12 байт, но заполнены они будут всяким мусором.
- В случае неудачи:
    - Обязательно проверяем, что получили не NULL
## free()
`free` освобождает память - возвращает её в кучу, откуда её снова можно выделить.
```c
free(arr);
```

После `free` эта память снова доступна системе: её может забрать другой процесс или ваша же программа под новый `malloc`.

### Утечка памяти
**Утечка памяти** - ситуация, когда программа выделяет память и не освобождает, например:

```c
int *ptr = malloc(10000); // выделим 10000 байт и адрес запишем в ptr
ptr = malloc(20000); // не освободим 10к байт мы перезаписываем в ptr новый адрес
```

### Двойное проникновение (освобождение)
`double free` - заодно развалив внутренние структуры аллокатора (это ещё и целый класс уязвимостей).
```c
int *ptr = malloc(100);
free(ptr);
free(ptr); // double free
```
Такие баги не нужно ловить глазами - соберите программу с санитайзером, и он покажет и причину, и строку:
```shell
gcc -fsanitize=address,undefined -g program.c -o program
./program
# ERROR: AddressSanitizer: attempting double-free on 0x602000000010 ...
#     #0 ... in main program.c:6
```
`valgrind ./program` умеет то же самое, но медленнее и без пересборки.

## calloc()

Почти как `malloc`: тоже выделяет память, но зануляет её и принимает два аргумента - **количество элементов** и **размер одного элемента**

```c
int *arr = calloc(3, sizeof(*arr)); // или calloc(1, 3 * sizeof(int));
```
И обратный трюк: память, выделенную через `malloc`, всегда можно занулить через `memset` (из `string.h`) - получится тот же `calloc`:

```c
int *arr = malloc(3 * sizeof(*arr));
if (arr == NULL) { /* ошибка */ }
memset(arr, 0, 3 * sizeof(*arr)); // начиная с адреса arr установить 12 нулей
```

`calloc` работает чуточку медленнее `malloc` (всё-таки зануляет память), но всё равно быстрее, чем `malloc` + `memset`.

## realloc()
Позволяет перевыделить память, сохранив прежние значения. Если кусок получится большой, адрес может измениться - тогда `realloc` скопирует все данные на новое место. Именно так растут динамические массивы во всех языках: `std::vector` в C++, `ArrayList` в Java, `list` в Python.

```c
#define N 10
#define M 5

// ..
char *str = malloc(N * sizeof(char)); // выделяем массив размером N байт
if (str == NULL) return -1;
// ..

str = realloc(str, M * sizeof(char)); // уменьшим массив до M байт
if (str == NULL) return -1;
// ..

free(str);
str = NULL;
```

**Важно:** если `realloc` потерпит неудачу, он вернёт `NULL` - и указатель в `str` мы потеряем, а это утечка. Поэтому делают так:

```c
char *tmp = realloc(str, M * sizeof(char)); // уменьшим массив до M байт
if (tmp != NULL) str = tmp;
```
